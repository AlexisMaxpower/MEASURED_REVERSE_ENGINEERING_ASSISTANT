## Chat 1 — Guided Capture Quality Baseline

### Goal

Turn Capture from a storage/calibration baseline into the first useful guided-capture assistant.

### Required work

1. Add deterministic capture-quality analysis primitives for at least:
   - blur/focus quality;
   - exposure clipping / underexposure-overexposure signal;
   - glare/highlight proxy;
   - framing / object or working-area occupancy where feasible with the current architecture;
   - calibration-marker visibility/quality reuse where appropriate.
2. Introduce an explicit capture acceptance result:
   - `ACCEPT` / `WARN` / `REJECT` or equivalent internal model;
   - machine-readable reasons;
   - human-readable Russian guidance may be produced by an adapter/presentation layer, not embedded as hidden logic.
3. Never represent image-quality inference as metric truth.
4. Preserve clean reference evidence as immutable.
5. Keep CapturePackage v1 compatible unless a Change Request is approved.
6. Add deterministic fixtures/tests for good and bad capture conditions.

### Do not do

- no measurement semantics;
- no OCR/caliper interpretation;
- no geometry inference ownership;
- no shared-contract changes without CR.

### Acceptance gate

- Chat 1 tests green;
- `Integration / Chat 1 -> Chat 2` green;
- no regression in full MREA CI.

## Chat 2 — Hands-Free Measurement Domain Baseline

### Goal

Implement the domain/application foundation for the user's hands-free measurement session without tying correctness to a specific speech/OCR provider.

### Required work

1. Add a provider-independent voice command parser/state machine for commands equivalent to:
   - capture trigger: `замер`;
   - value candidate: `замер 42,18` / normalized numeric forms;
   - confirm;
   - reject/correct.
2. Voice/OCR/device values enter as **candidates**, not automatically verified facts.
3. Preserve manual entry as authoritative fallback.
4. Explicitly model candidate -> confirmation -> verified transition.
5. Evidence frame and reference frame linkage remain mandatory where applicable.
6. Keep raw image anchors in `IMAGE_PX`; do not absorb Chat 3 normalization.
7. Add deterministic parser/state-transition tests, including ambiguous/invalid input.

### Do not do

- no speech-engine implementation from scratch;
- no geometry normalization;
- no automatic caliper CV ownership in this pass unless it is isolated experimental code and cannot block the required gate.

### Acceptance gate

- Chat 2 tests green;
- `Integration / Chat 1 -> Chat 2` green;
- `Integration / Chat 2 -> Chat 3` green.

## Chat 3 — Semi-Automatic Geometry Candidate Extraction

### Goal

Begin real semi-automatic sketch preparation from normalized image geometry.

### Required work

1. Add deterministic primitive-candidate extraction from a normalized/reference image or a stable image fixture for the v1 subset:
   - LINE;
   - CIRCLE;
   - ARC where reliable enough for the chosen fixture;
   - POINT/endpoints as derived geometry where useful.
2. Reuse OpenCV/geometry libraries where appropriate; do not write generic CV algorithms from scratch without a Build/Reuse justification.
3. Extracted primitives must be marked as `VISION_DETECTED` or another truthful non-measured provenance.
4. Bind verified physical measurements to detected geometry without changing verified values.
5. Ambiguous/unsupported candidates remain explicit/unresolved; no silent geometry invention.
6. Output remains canonical SketchPackage v1.
7. Add golden image/geometry fixtures and deterministic tests.

### Do not do

- no AI guessing hidden geometry;
- no CAD-specific logic;
- no change to measurement truth hierarchy.

### Acceptance gate

- Chat 3 tests green;
- `Integration / Chat 2 -> Chat 3` green;
- `Integration / Chat 3 -> Chat 4` green.

### Goal

Make the already integrated SOLIDWORKS 2026 agent genuinely ready for a controlled real-host validation while keeping the generic CAD path green.

### Required work

1. Preserve generic/test-double CAD behavior and current canonical mapping.
2. Add/strengthen a fail-closed preflight path for the real host:
   - Windows/x64 check;
   - .NET/agent build prerequisites;
   - SOLIDWORKS availability/version detection where technically feasible;
   - interop availability diagnostics;
   - writable artifact/output path diagnostics;
   - clear exit codes and machine-readable failure reasons.
3. Make the golden smoke procedure one-command or minimal-command and deterministic.
4. Ensure runtime evidence can record:
   - SOLIDWORKS version;
   - input SketchPackage identity;
   - generated native artifact identity/hash;
   - read-back dimensions;
   - verification report;
   - failure diagnostics.
5. Do **not** mark real runtime VERIFIED until an actual Windows 11 + SOLIDWORKS 2026 run occurs.
6. Support POINT/ARC/additional constraints only if doing so does not weaken the host-validation objective or fail-closed behavior.

## Chat 5 — Physical Part Instance Lifecycle

### Goal

Extend lifecycle beyond a revision/manufacturing record into the real-world life of a manufactured part.

### Required work

1. Introduce a physical manufactured part instance identity tied to:
   - revision;
   - manufacturing record;
   - material/method metadata already available.
2. Support deterministic lifecycle transitions for:
   - manufactured;
   - installed on equipment/position;
   - tested;
   - active/in service;
   - failed;
   - removed;
   - replaced/superseded where appropriate.
3. Preserve failure evidence and relationship to revision/physical instance.
4. Prevent invalid transitions explicitly.
5. Keep failed/unverified CAD revisions from bypassing manufacturing eligibility.
6. Add timeline/state-transition tests.
7. No AI analysis yet; facts first.
